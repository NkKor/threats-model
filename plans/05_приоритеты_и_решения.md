# Приоритеты и решения (актуальные)

Дата: 2026-10-08. Документ фиксирует решения заказчика и актуальный план работ.
Статусы задач из [`03_отчёт_о_доработке.md`](03_отчёт_о_доработке.md) (раздел 9)

## 1. Решения заказчика

| Вопрос | Решение |
|---|---|
| Сопоставление СП1–СП9 ↔ СП.1–СП.26 | **Отложено.** Методист готовит материалы для сверки — выполним после их получения |
| Подтверждение трактовок R3/R4 | **Отложено.** Проверим позже, вместе со сверкой материалов |
| Экспорт по шаблону `Модель угроз Юнитех.docx` | **Не трогаем.** Работаем с отчётом по `report-rules.txt` |
| Аутентификация / разграничение доступа | **Отменена.** Работают методисты, данные обезличены, персональных и коммерческих данных нет |
| Миграции (Alembic) | **Отменены полностью,** из планов исключены: изменения редки, легаси и техдолг не угроза, сложность проекта не требует миграционного слоя. Схема обновляется автоматически при старте |
| Docker | **Удалён из проекта** (Dockerfile, docker-compose.yml, `.dockerignore`, упоминания в README). На рабочих машинах Docker недоступен из-за ограничений прав и политик |
| Форма запуска | **PowerShell + обычное Python-окружение:** `threat-modeler/start.ps1`, сервис на `0.0.0.0:8080`, коллеги из локальной сети обращаются по `http://<IP-машины>:8080` |
| Итоговые таблицы (стр. 5 отчёта) | **Компактный вид:** в колонках «виды воздействия», «способы реализации», «негативные последствия», «тактика», «техника» — только индексы через запятую (например `Т1, Т2, Т3`). Идентификатор/наименование УБИ, уровни возможностей нарушителей и объект воздействия — без изменений |
| Git | **Выложен** в публичный репозиторий `https://github.com/NkKor/threats-model`, ветка `main`; выкладка — `publish.ps1` |

## 2. Первый приоритет (текущий)

1. **Уход от Docker** — ✅ выполнено: `threat-modeler/docker/` и `.dockerignore`
   удалены, запуск через `threat-modeler/start.ps1` (venv → зависимости → БД →
   uvicorn на `0.0.0.0:8080`), README приведены к PowerShell-запуску.
2. **CI** — ✅ выполнено: `.github/workflows/ci.yml` (инициализация БД, проверка
   источников, 62 теста, HTTP-смоук `scripts/smoke_http.py`); прогоны зелёные.
3. **CD на рабочий ПК** — ✅ выполнено: `deploy.ps1` + `.github/workflows/deploy.yml`
   (self-hosted раннер, `workflow_run` после успешного CI на `main`), запуск через
   задачу планировщика «ThreatModeler» и проверку `/health`. Инструкция —
   [`06_ci_cd_рабочий_пк.md`](06_ci_cd_рабочий_пк.md); осталось установить раннер
   и включить required status checks в GitHub UI (действия на стороне ПК/UI).
