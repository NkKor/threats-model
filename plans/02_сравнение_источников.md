| СП2 | Перехват информации | внедрение вредоносного ПО |
| СП3 | Копирование информации | использование недекларированных возможностей |
| СП4 | Модификация информации | установка программных/аппаратных закладок |
| СП5 | Уничтожение информации | формирование и использование скрытых каналов |
| СП6 | Блокирование информации | перехват ПЭМИН |
| СП7 | Внедрение вредоносного ПО | инвазивный доступ к аппаратным средствам аутентификации |

переделать в первую очередь.

## 3. Итоговая модель данных, которую принимаем

Источник истины: `бдму.xlsx` (корреляция) + `справочники/*` (словари) + `сводная таблица.docx`
(уровни нарушителей) + `УБИ-объект.docx` (наименования и источник угрозы).

```
Тип ИС (14) ──┐
              ├─→ применимые последствия (уX.Y, 66) ──┐
Вид риска У1/У2/У3 ─┘                                  │
                                                       ├─→ перечень УБИ (227)
Уровень нарушителя (сводная таблица) ──────────────────┤
Объекты воздействия (38, бдму) ────────────────────────┤
Интерфейсы (6 типов) → допустимые СП (1–9) ────────────┘
                                                       └─→ тактики Т1–Т10 / техники (89–144)
```

Шаги опроса (суть проекта сохранена: контейнер с веб-сервисом, wizard → отчёт + предпросмотр):

1. **О системе** — тип(ы) ИС (14) + технологические признаки; ПДн сохраняются как один из типов ИС.
2. **Нарушители** — 13 видов (внешние/внутренние) + уровни Н1–Н4 отдельно для внешних и внутренних.
3. **Интерфейсы** — 6 типов по Методике.
4. **Объекты воздействия** — 38 объектов (с авто-подстановкой по технологиям из шага 1).
5. **Отчёт** — предпросмотр на странице: Таблица 1 (виды риска и последствия по типам ИС) +
   Таблица 2 (перечень УБИ) + экспорт в XLSX/DOCX.

## 4. Правила фильтрации (принимаются и документируются в коде)

1. **Тип ИС → последствия.** Объединяем применимые `уX.Y` по всем выбранным типам ИС.
   Пустой выбор = фильтр отключён.
2. **УБИ проходит по последствиям**, если хотя бы одно её последствие (по всем парам объект/УБИ)
   входит в множество применимых.
3. **УБИ проходит по объектам**, если объект хотя бы одной её пары выбран пользователем.
4. **УБИ проходит по нарушителям**, если для хотя бы одной заявленной категории (внутренние/внешние)
   с уровнем L найдётся указанный в `сводной таблице` уровень `Li` со `rank(Li) <= rank(L)`
   (нарушитель с более высокими возможностями может реализовать всё, что доступно более слабому).
   `―` = угроза данным типом нарушителя не реализуется.
5. **УБИ проходит по интерфейсам**, если для её пары (УБИ, объект) хотя бы один способ реализации
   доступен через хотя бы один выбранный интерфейс.
6. Если выбор пуст по любому измерению — соответствующая проверка не ограничивает (поведение
   сохраняется от исходного проекта, чтобы wizard не «обнулял» отчёт).
